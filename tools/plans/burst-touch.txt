# Burst experiment for the Touch (Phase 2, after the census): for the gestures that send a RUN
# of keys, is the run driven by time, distance, or holding? Mirrors burst-tune.txt (2026-09-05),
# where the Tune's 2-finger swipes streamed 5-27 presses scaled to travel and everything else
# sent exactly one key. Phase 1 on the stock profile (2026-09-09) found the Touch's 4-finger
# swipe up/down send a run of chords (8 presses in 277 ms) while 3-finger swipes and 4-finger
# left/right send one, and a single slow swipe up gave only 2 presses, so speed vs distance is
# the open question.
#
# Uses the 2026-09-10 flash (census-touch.module-profile.json: 2-finger axes Ctrl+F13-F16,
# 3-finger swipes Alt+F13-F16, 4-finger swipes Alt+F18-F21), no re-flash. 1-finger fields, the
# 2-finger swipe fields and pinch&spread are not flashed (see census-touch.txt), so their
# sections are under "Later:" and wait for the full map.
#
# Run:  powershell -ExecutionPolicy Bypass -File tools\input_capture.ps1 -PlanFile tools\plans\burst-touch.txt -Seconds 4 -Out tools\plans\burst-touch.log; python tools\input_analyze.py tools\plans\burst-touch.log
# Or:   powershell -ExecutionPolicy Bypass -File tools\gesture_capture.ps1 -PlanFile tools\plans\burst-touch.txt -Seconds 4 -Out tools\plans\burst-touch.log; python tools\keymon_analyze.py tools\plans\burst-touch.log
